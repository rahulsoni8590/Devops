## why kubernetes:

- Scalability = scale based on traffic
- Self-healing = restart without manual intervention.
- Declarative configuration.
- Multicloud and hybrid support - eg AWS,Azure,GCP , hybrid support means some part of code running on cloud and some on bare-metal[local-machine.]

## Concepts:

- Cluster [laptop] >>> Nodes >>>> Pods >>> [Container + Volumes]

1. Node - A virtualmachine where k8s cluster will run.
    - Node have any number of pods init.
    - Node is like a AWSinstance.
    - two types on node:
        1. Master Node. = k8s services such as restarting,loadbalancing. Only one master node.
        2. Worker Node. = main container. These nodes can be multiple.
          - Multiple worker Node result in highavailability.

2. Pod = Smallest unit of K8S. just like container for docker.
    - pod will have container and volumes in it.
    - Pods can have multiple container init but mostly it has only single container.
    - pod is a building block for cluster.

3. Cluster = Node as a whole is called as cluster 
    - ie [master node + All other worker Node]

4. Service 
        - for stable endpoint and Loadbalancing
    - In docker, container's app/service port is opened to localmachine so to access it in the local machine. 
    - In container if container is killed and brought up its ip-address is changed. THus whose system is break.
    - But in pods with the help of service we will have access to pods via Ip-address name or port and this services works as a stable endpoints so if the pod goes down the ip is changed but the name remains the same so localmachine is able to identify the pod again and load balancing works the same way.
    - Service doesnot restart pods but it setup the communication with the pod.

5. Replica:
    - define number of replicas for the pod like how many should remain up and on increase traffic how many should increase.
    - It is wrapper over the pod.
    - It has default 3 pods init.
    - If one go down another is up but max 3.

6. Deployment:
    - It is a wrapper over the pods.
    - It can perform rollingout strategies,recreate strategy and version control and roll back.
    - It remember the changes when app1 changes to app2 after deployment. which helps in rollback.


7. Namespace:
    - layer of isolation.
    - Namespace is given to identify a deployment inside a cluster to fetch that pod or to work into that particular pod.

8. Statefull set [secret&configMaps]:
    - Stable Endpoint.
    - Deploye database
    - persistent storage.
    - In pod if it goes down it  restart but all the data is gone but in statefull set have the data persistent. storage is associated with it so data is not lost.

9. configmaps and Secret:
    - for storing information in key value pairs
    - Two types of data storage:
        - ConfigMap = for insensitive data eg config
        - Secret = for sensitive data eg sshkey,privatkey it use encoding base-64


## creating pod with Kubectl

- In yml file hypen means a list.
- <kubectl version> = to check version of kubectl

### creating pod using image
- <kubectl run pod podname --image=imagename> = to create a pod
- <kubectl get pods> = to get all pods
- <kubectl get namespaceName> = to get all name pods
- <kubectl create namespace custompodname> = to create namespace here custompodname is namespace name
- <kubectl get pods -n namespaceName> = to get all pods with namespace as n

### creating pod in declarative way using YML file
- <kubectl create -f podname.yml> = to create the pod
- <kubectl delete pod podname.yml -n namespaceName> = to delete the pod
- <kubectl config set-context namespaceName>
- <kubectl config set-context --current --namespace>

```yml
apiVersion: v1
kind: Pod
metadata:
  name: my-pod
  namespace:cn
spec:
  containers:
    - name: first-container
      image: nginx
      ports:
        - containerPort: 80

```

## creating pod for deployment and services

- <kubectl create -f .\fileName.yml> = to create deployment
- <kubectl get deployments> = to get all deployments
- still we are not able to connect or see the deploymet so to do this we need to create a service for that.
- There are 3 types of services:
    1. Node Port = expose a port in local machine.
    2. cluster IP = service will have ip-internal[ip is stable] other cluster can't only the host or localmachine [internally two service can communicate]
    3. Load balancer = external ip address so other cluster can also connect.

- <kubectl create -f .\fileName.yml> = to create service

- now to rollout the deployment pod
- <kubectl rollout status deployment deploymentpod-name> = to rolled out the deployment pod
- <kubectl rollout history deployment deploymentpod-name> = to check the rolled out history.

- now to edit the deployment
- <kubectl edit deployment deploymentpod-name> = to edit it
- this will open up a txt file, just change the image to inginx:latest and save it
- now check history with above commands
- <kubectl rollout undo deployment deploymentpod-name> = to undo the rollout 
- now if checkhistory there will be last deployment number will be gone and a new number is add [lastnum +1].

- <kubectl describe deployment deploymentpod-name> = to seee the config of the yml deployment file.

- selector are like labes to pods 

```yml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: my-deployment
spec:
  strategy:
    type: Recreate
  replicas: 3
  selector: 
    matchLabels:
      app: my-app
    template:
      metadata:
          labels:
            app: my-app
      spec:
          containers:
          -  name: first-container
             image: nginx
              ports:
              - containerPort: 80
```

# Secret with Deployment pod

- for config with Deployment instead of "secretKeyRef" it will be "configKeyRef".

```yml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: my-deployment
spec:
  strategy:
    type: Recreate
  replicas: 3
  selector: 
    matchLabels:
      app: my-app
    template:
      metadata:
          labels:
            app: my-app
      spec:
          containers:
            - name: first-container
              image: nginx
              ports:
                - containerPort: 80
              env:
              - name: USERNAME
                valueFrom:
                  secretKeyRef:
                    name: my-secret
                    key: username

```
