## Networking

-  Port are like door which is used to connect to app. if port is not open/Expose then we can use the service/app

1. IP Address = 
    -To uniquely identify a machine on a network. but For machine the unique-identifier is mac-address.
    - Ip address changes but mac address is constant.
    - Every network interface eg[phone,pc,tab] have mac address.
    - Single machine can have multiple IP address becoz being connected to internet or local-network [eg ac,smarttv,mobile,pc connect to wifi-router]
    - zero to 255 in all four blocks  ==>> 0.0.0.0 [syntax-OF-IP]

2. Subnet = 
    - It is like subnetwork eg router can have max 255 address ie 192.168.1.[0-255].
    - CIDR notation for  192.168.1.[0-255] is 192.168.1.0/24 it means 8*8*8 first three blocks are constant only the last can change. 8 bit are fixed.
    - CIDR notation for 192.168.[0-255].[0-255] is 192.168.0.0/16 it means 8*8 first two blocks are constant only the last two can change. 16bit are fixed.
    - SO if 192.168.1.0/32 it means 8*8*8*8 all are fixed that this SUBNET has only one ip address.
    - Subnet is a range of IPaddress it is used to define the network by the range.
    - 192.168.1.0/32 currently 32 & 16 are mulitple of 8 now if it is /35 or /25 then binary so read [binary] to learn more.

3. DNS = [DomainNameSystem] eg:google.com
    - DNS correspont URL to IPAddress
    - DNS server is a table which stores the domain and the IP
       eg WWW.google.com | 10.1.2.5

4. Ports = 
    - Ports are gateway or door to the machine.
    - we can have custom as well as standard port.
    - Govt has defined some default port number for some services. 
        for eg - port 22 is assigned to ssh by default.
            - for http port 80 is taken by default
            - for https port 443 is taken by default
    - In hacking, backdoor term is used when a application have some module or code which has some other port exposed than that port work as a backdoor to my machine until the internet is connected

## Docker Network [first three are imp]

1. Bridge Network = while creating the container we are in bridge network it is by default
    - for two container is a same machine have two different ipaddress which connected to a gateway/cloud of the same machine so this is called as private subnet. the two container can have access to eachother.
    - Private network, No access to host.
    - no DNS server by default ie two container have to use IPaddress to communicate and not the container-name.
    - incase of custom-network DNS server is there so two container can communicate through names.

2. None = container does not have connection to outer machine. 

3. Host = container access to main machine. but in opposite of it we earlier exposed the port on the container and then we forwarded or attaached that port to our machines port eg 3000:3000 [1.18video]

4. overlay = help connect one docker container on one machine to another docker container in other machine ie cluster of machines running multiple container so to machine to know which container to connect it is concept of [Docker-Swarm].

5. Custom-Network

- docker network create --driver=brigenetwork custom-name = --driver=brigenetwork to specify which network to use otherwise by default bride network is used
- docker network connect network-name container-id = to connect container to network

```shell
docker network ls
docker network create custom-name
docker network create --driver=brigenetwork custom-name

```

## Docker Storage:

## Three types/ways of storage:

- In docker container data is not persistent as soon as container is stopped or crashes or deleted, data is gone eg log data.
- So persistent the storage, docker volume,bind-mount,tempfs are used. temp is virtual RAM 

### Volume
- Data can only be seen when volume is mount to container and then inside the container we can access the data . Direct access via browser or outside-container not possible.
- Volume is filesystem for the container
- volume is isolated from main file system of local machine.
- backup of volume can also be possible.
- volume can be used for data storage of the db. Incase db is changed we can dump data from volume to other db.
- volume can be connected/mounted to multiple containers at single time.
- eg volume is mounted to containers path html/web
- In production Majorly in practise.

### Bind mount

- It allow user to mount/bind a directory of local machine to the container.
- In bind-mount, local machine Directory is filesystem for the container
- eg /home/raj directory of local machine is mounted/bind to /home/raj of container.
- It is not isolated ie can be accessed outside the container.
- So files inside local directory is changed it is visible in container.
- Good for Development.

### tempfs
- It is stored in host system memory/RAM but not the harddisk.
- used maninly for caching , need fast data without worrying about persistency just like kafka and redis as RAM is very fast than the harddisk.
